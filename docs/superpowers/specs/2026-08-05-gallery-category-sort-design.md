# 相册分类排序 + 乱码按钮修复 设计文档

日期：2026-08-05
范围：`source/gallery/index.html`（单文件改动）

## 1. 背景
- 管理面板照片卡片上有两个按钮显示为乱码（`&#8630;` / `&#8631;` 原样文本）。
- 用户需要「分类排序」功能：分类在左侧边栏的显示顺序可自定义，顺序持久化到云端。

## 2. 功能设计

### 2.1 乱码按钮修复
- 根因：JS 字符串中按钮字符写成了 `&amp;#8630;`（双重转义），innerHTML 解析后显示为字面文本。
- 修复：改为 `&#8630;`（左旋转 90°）与 `&#8631;`（右旋转 90°）。

### 2.2 分类排序（方案 A：仅影响侧边栏列表）
- 数据：`manifest.json` 新格式中的 `cats` 数组升级为「完整有序分类列表」（含空分类，不含“全部/未分类”）；旧格式数组与旧 `cats` 语义自动兼容。
- 排序 UI：管理面板 → 分类管理区，每个分类行新增 ↑ / ↓ 按钮（“未分类”行禁用，固定最后）。
- 交互：点击 ↑ / ↓ 调整 `catOrder` → 立即重建分类管理区与侧边栏 → 点「保存更改」持久化到云端。
- 侧边栏渲染顺序：全部 → `catOrder` 顺序 → 其余分类（按出现顺序）→ 未分类（最后）。
- 照片播放顺序不受影响（仍由现有 ↑ ↓ 按钮控制）。

## 3. 代码变更点
- `extraCats` 变量更名为 `catOrder`（语义升级为有序列表）。
- `buildCats()`：按 catOrder 排序生成 catList。
- `saveManifest()`：`payload.cats = catOrder`。
- `renderCatManage()`：按 catList 渲染 + 每行 ↑ / ↓ 按钮与事件；创建/重命名/删除分类时同步维护 catOrder。

## 4. 测试要点
- 管理面板旋转按钮显示为箭头图标，点击可旋转照片。
- 分类 ↑ / ↓ 排序后侧边栏顺序即时变化；保存后刷新页面顺序保持。
- 创建空分类 → 排序 → 保存 → 刷新仍存在且顺序正确。
- 重命名/删除分类后 catOrder 同步，无残留。
- 旧 manifest（纯数组）打开不报错。
